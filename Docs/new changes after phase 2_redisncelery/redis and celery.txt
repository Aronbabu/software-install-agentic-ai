Production Risks
Risk 1 — Queue Lost on Restart
Current queue lives inside application memory.
If server restarts:
Queued Jobs
     ❌ Lost

Risk 2 — Multiple FastAPI Instances
Suppose tomorrow you deploy:
Pod 1
Pod 2
Pod 3
Each instance gets:
_job_queue
_active_jobs
_workers

Pod-1 queue != Pod-2 queue
Not scalable.

Risk 3 — No Durable Retry
Queue + Retry = memory
Server restart means:
retry state may disappear

Risk 4 — No Horizontal Scaling
Today:
1 API
1 Worker Process

Tomorrow:
100 RITMs
1000 RITMs

Worker threads become bottleneck.
------------------------------------
Why Redis + Celery?
current usecase
Software Installations
Remote Execution
Long Running Tasks
Retries
Scheduling

Celery fits extremely well.
Benefits
✅ Durable queues
✅ Distributed workers
✅ Native retries
✅ Native delayed jobs
✅ Scheduled execution support
✅ Horizontal scaling
✅ Monitoring ecosystem
